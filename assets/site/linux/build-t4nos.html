Gue udah sering ditanya: "kenapa sih repot bikin distro sendiri, kan udah ada Void?" Jawaban gue selalu sama - gue gak bikin dari nol. T4n OS dibangun di atas Void Linux, dan yang gue kerjakan adalah melapisinya jadi distro yang beneran gue mau pakai dan gue bagikan: init runit, tema GRUB sendiri, varian desktop siap pakai, sampai installer-nya.

Alatnya satu: t4n-live - kumpulan skrip shell penerus void-mklive yang gue rawat di repo T4n-Labs/t4n-live. Post ini adalah catatan lengkap proses build-nya: dari repo kosong, xchroot, sampai ISO bisa di-boot.

Kenalan dulu sama alatnya

t4n-live bukan satu skrip tunggal, tapi toolchain. Masing-masing skrip punya tugas spesifik:

Skrip Fungsi
t4n-iso.sh Live ISO lengkap + installer (i686, x86_64, aarch64)
t4n-live.sh Live ISO dasar/minimal - mesin di balik t4n-iso.sh
t4n-rootfs.sh ROOTFS tarball, semua arsitektur (tanpa kernel)
t4n-platformfs.sh ROOTFS + kernel, per-platform (untuk ARM)
t4n-image.sh Image ARM siap-flash via dd
t4n-net.sh Tarball netboot/PXE
installer.sh / installer.py Installer T4n OS (bash & python)

Skrip-skrip ini bekerja lewat xchroot (chroot cross-architecture): bikin rootfs kosong, install paket ke dalamnya pakai xbps-install -R, lalu injeksi konfigurasi. Semua yang lo lihat di ISO, LightDM, tema GRUB "Sleek", service runit itu hasil injeksi dari direktori common/.

Persiapan: host build-nya wajib Void

Ini hal pertama yang harus diakui: t4n-live gak dijamin jalan di distro lain atau di dalam container. Skripnya manggil xbps, xchroot, dan module dracut kustom, semuanya environment Void. Jadi host gue sendiri Void Linux x86_64 (bisa juga VM biar aman).

Dependensi minimal:

sudo xbps-install -Su xbps bash xz qemu-user-static
qemu-user-static cuma wajib kalau mau build rootfs lintas-arsitektur (misal bikin aarch64 dari host x86_64). Kompresi initramfs default xz — kalau mau lebih cepat pas boot, ada opsi lz4 (butuh liblz4).

Build ISO pertama

Clone repo, langsung gas. Ini perintah build paling dasar ISO x86_64 varian XFCE lengkap dengan installer: 

git clone https://github.com/T4n-Labs/t4n-live.git
cd t4n-live
sudo ./t4n-iso.sh -a x86_64 -b xfce

Arti flag-nya:

  • -a x86_64 — arsitektur target (menentukan XBPS_ARCH dan repo yang dipakai)
  • -b xfce — varian yang di-build (menentukan paket base + config yang diinjeksi)

Di belakang layar, t4n-iso.sh cuma wrapper, dia ngoper semuanya ke t4n-live.sh plus satu paket tambahan: t4n-installer. Outputnya ISO siap burn ke USB atau tes di QEMU.

Varian yang tersedia

Varian (-b) Deskripsi
base Sistem dasar tanpa DE
server Headless (masih dalam pengembangan)
xfce Desktop XFCE, X11 + LightDM
xfce-wayland Desktop XFCE, Wayland

Kustomisasi: bumbui ISO-nya

Di sinilah serunya. Semua opsi di t4n-live.sh bisa diteruskan dari t4n-iso.sh lewat --: 

sudo ./t4n-iso.sh -a x86_64 -b xfce -- \
  -p "firefox neovim git htop" \
  -I ./my-overlay/ \
  -C "live.autologin live.shell=/bin/bash" \
  -o T4nOS-xfce-custom.iso
  • -p — paket ekstra yang di-install ke dalam ISO
  • -I — seluruh isi direktori ini disalin ke rootfs (cara gue masukin wallpaper, skrip, dotfiles)
  • -C — argumen kernel command line tambahan
  • -o — nama file output

Ada juga -S buat aktivasi service, -e buat ganti shell default root, dan -K kalau mau ngintip isi builddir buat debugging. Daftar lengkapnya ada di ./t4n-live.sh -h.

Parameter kernel yang paling sering gue pakai

Karena ini live system, banyak perilaku dikontrol dari kernel cmdline pas boot:

Parameter Fungsi
live.autologin Lewati login screen di tty1
live.user=nama Ganti username non-root (default: anon)
live.shell=path Shell default user live
locale.LANG=.. Set locale (default: en_US.UTF-8)
console=ttyS0 Aktifkan serial console

Semua ini dihandle modul dracut kustom di dracut/vmklive/ - adduser.sh bikin user live-nya, locale.sh set locale, display-manager-autologin.sh urus autologin LightDM. Gak ada sihir, cuma skrip shell yang dijalankan saat initramfs boot.

Jalur ARM: 3 langkah ke Raspberry Pi

Build ISO x86 itu jalur "hangat". Untuk ARM alurnya beda, dengan tiga tahap, dan ini bagian favorit gue karena di sinilah qemu-user-static + xchroot jadi bintang: 

# 1. ROOTFS: sistem Void dasar TANPA kernel (aarch64)
sudo ./t4n-rootfs.sh aarch64

# 2. PLATFORMFS: ROOTFS tadi + kernel khusus platform
sudo ./t4n-platformfs.sh rpi-aarch64 void-aarch64-ROOTFS-*.tar.xz

# 3. IMAGE: filesystem utuh 2 partisi (/boot + /), siap flash
sudo ./t4n-image.sh void-rpi-aarch64-PLATFORMFS-*.tar.xz

Terus flash ke SD card:

dd if=void-rpi-aarch64-*.img of=/dev/sdX bs=4M status=progress
⚠️ Ganti /dev/sdX dengan device SD card yang bener. Cek dua kali pakai lsblk, salah target = data hilang.

Kenapa dipisah tiga? Karena ROOTFS itu generik (satu build untuk semua arsitektur), sedangkan kernel itu spesifik platform. Dengan memisahkannya, gak perlu rebuild rootfs 1GB buat tiap-tiap board cukup tukar lapisan kernelnya. Platform yang udah didukung: rpi (armv6l/v7l/aarch64), pinebookpro, pinephone, rock64, rockpro64, sampai asahi.

Eksperimen lain: netboot, Packer, container

Toolchain-nya ngerambah lebih jauh dari sekadar ISO:

  • Netboot/PXE — t4n-net.sh bikin tarball PXE, cocok buat boot T4n OS di jaringan lokal tanpa media fisik.
  • VM image — konfigurasi Packer di packer/ bikin image QEMU/VirtualBox/Vagrant otomatis, lengkap dgn preseed: 
packer init packer/plugins.pkr.hcl
packer build packer/hcl2/source-qemu.pkr.hcl
  • Container — build environment-nya sendiri bisa dikemas jadi OCI image, biar build reproducible di CI: 
podman build -f container/Containerfile -t t4n-live:latest
# atau multi-target:
docker buildx bake -f container/docker-bake.hcl

Anatomi repo (versi singkat)

Buat yang mau ikut baca kodenya, ini peta yang paling relevan:

  • common/cli/ — seluruh konfigurasi yang diinjeksi: LightDM, polkit, Xorg, dan runit/ (stage 1/2/3 + core-services + service default)
  • common/cli/sleek/ — tema GRUB kustom: background, font Poppins/Terminus, 60+ ikon distro buat multiboot
  • dracut/ — modul initramfs: vmklive (jantung live system), autoinstaller, netmenu
  • grub/ & isolinux/ — template bootloader (UEFI & legacy BIOS)
  • lib.sh — fungsi bersama: mount, xchroot, injeksi config

Dokumentasi lengkap (bahasa Indonesia & Inggris) ada di vdocs/ di dalam repo.

Penutup

Build distro ternyata bukan soal ilmu hitam, itu cuma rangkaian xbps, chroot, dracut, dan banyak banget skrip shell yang sabar. Yang bikin T4n OS "beda" bukan kernelnya, tapi keputusan-keputusan kecil: init apa, service apa yang nyala, login-nya kayak gimana, bootloader-nya tampil kayak apa.

Kalau lo pengen nyoba, mulai dari yang paling gampang: sudo ./t4n-iso.sh -a x86_64 -b xfce di VM. Kalau berhasil boot dan lo ngerasa "oh, cuma gitu doang?" selamat, lo udah bisa bikin distro sendiri. Source Code rilisnya: github.com/T4n-Labs/t4n-live .
